# 開示日時による財務入力の再構成

2024年12月末〜2026年8月末の21評価日について、79,315銘柄時点の財務入力を保存した。
正式なハードゲート・100点採点・売買判断はまだ生成していない。
この入力だけで過去検証やLIVE条件を完了扱いにしない。

| 確認・抽出した範囲 | 件数 |
| --- | ---: |
| 固定世代の原本から再構成した財務開示 | 94,982 |
| 同じ原本から再構成した株数観測 | 80,941 |
| 月末の財務入力 | 79,315銘柄時点 |
| 4四半期からTTM売上を算出できた入力 | 25,762銘柄時点 |
| 連続8四半期のサマリー数値を接続できた入力 | 14,719銘柄時点 |
| 次の資料確認へ渡すコード | 3,934 |
| 期間種別・期間日付の要確認レコード | 14 |

集計の正本は [summary.json](summary.json)、計算は
[financial_inputs.py](../../src/stock_jp/research/financial_inputs.py)。
生応答は採用済み世代 `7de87dce283a1cd8ae488767cec934158c3d4a598e97fc8e6d269c59dc4b23a4` に固定した。
通常取得が更新する `current.json`、観測CSV、復元キャッシュには依存しない。
原本から既存の観測変換処理で再構成し、当日の観測CSVとの一致も
[normalization-audit.json](normalization-audit.json) に記録した。

## 母集団と時刻

2025年8月〜2026年8月の13評価日は、原本の日付別銘柄マスターから国内普通株を選ぶ。
商品区分・普通株の識別・PRO Market除外は日次取得と同じ処理を使う。
価格がない銘柄も母集団に残す。

2024年12月〜2025年7月の8評価日は、旧公式価格CSVに登場する国内銘柄が対象。
価格に登場しない銘柄や上場・廃止履歴の網羅性は未確認である。
全期間の恒久的な銘柄ID・コード再利用・合併の接続も未確認のまま残す。
旧配分診断の79,369銘柄時点との差54件は、日付別マスターと日付別価格出力を優先した差であり、
将来リターンによる除外ではない。配分診断の元入力や結果は変更していない。

cutoffは各評価日の東証取引終了時刻15:30 JST。
開示日時がcutoff以下の決算実績だけを使い、開示番号の大小では順序を決めない。
取得日は2026年10月であり、当時に取得済みだったという意味ではない。
同じ会計期間の最新開示を選び、過去期間の訂正で最新の決算期間を置換しない。
同一時刻の複数開示で判定できない場合は数値を選ばず確認待ちにする。

## 数値の接続

- 業績・配当予想の修正を四半期実績として数えない。
- 四半期値は、同じ年度・会計範囲の累計値から前四半期累計を引く。1Qは報告値を使う。
- TTMは接続できた直近4四半期の合計。前年TTMはさらに前の4四半期の合計。
- 連結・単体、会計基準、連結範囲、方針・見積り・再表示、訂正前後の接続を推測しない。
- 変則期間、前四半期や金額の欠損では系列を止める。8四半期の件数は数値系列の上限8件を数える。
- 金額は原本の円建て文字列をそのまま使う。空欄をゼロや過去の現金で埋めない。
- 株数は決算期間の報告値。完全希薄化後株数や評価日現在の発行済株数とは扱わない。

TTM前年比は総売上の参考計算で、希薄化後1株当たりの成長スコアではない。
営業CFと投資CFの合計をFCFに読み替えず、年度CFから6か月の資金余力も推定しない。
数値系列の接続だけで監査・KPI等の比較可能性を認定しない。

## 次に確認する一次資料

[review-queue.csv](review-queue.csv) は全コードの最後の評価時点で、次に必要な入力を分類する。
月別CSVは過去の各評価時点を保持する。最終月に消えたコードも確認一覧から削除しない。

| 最後の評価時点での確認対象 | コード数 |
| --- | ---: |
| 会計範囲・方針・訂正・変則期間の接続資料 | 3,008 |
| 8四半期のサマリー再構成 | 158 |
| 純資産・継続企業の一次確認 | 6 |
| 財務開示の識別・欠損 | 7 |
| ハードゲート・粗利益・希薄化・SAM・採点の一次資料 | 755 |

これらは買付候補の分類ではない。前段の欠損を確認した銘柄にも、監査意見、資金余力、
潜在株式、粗利益、事業KPI、SAM/SOM、競合、10倍逆算の確認が必要である。
純資産が負の報告値も、自動的に正式な不合格判定へ変換していない。
[source-anomalies.csv](source-anomalies.csv) には、期間種別不一致10件と期間日付矛盾4件を原本参照付きで残す。
REITなど本体対象外の原本も含む確認一覧であり、全件を母集団に追加するものではない。

フィーチャ4052の2026年8月末入力は、8月14日開示の単体サマリーを採用する。
以前の連結四半期へ接続せず、`BASIS_CHANGE_REQUIRES_BRIDGE` とする。
9月の有価証券報告書から確認した数値をこのcutoffへ遡って入れない。
後日の確認範囲は[一次資料レビュー](../validation-2026-10-05/4052-primary-review.json)を参照する。

## 公表時点データと残る制約

[公式仕様](https://jpx-jquants.com/en/spec/fin-summary)は、会社の訂正開示を新しい開示番号で保存し、
訂正前レコードを上書きしないと説明している。今回も開示日時でバージョンを選んだ。
ただし、[provider側の訂正履歴](https://jpx-jquants.com/en/spec/fix-data-info)には
2025年5月2日の財務データ全体修正がある。影響銘柄・期間はこの記載だけでは特定できない。
このため当時の元値・provider修正履歴を確認済みとは認定しない。
仕様を確認した日時と判断は [provider-review.json](provider-review.json) に記録する。

正式検証には、この入力を使った全月末のハードゲート・採点、重要開示と出口の判定、
当時公表済みのMRS、上場・廃止・企業行動の接続が残る。
forward holdoutと本人の承認も別条件である。運用はPAPER、復旧試験は利用者の指示どおり対象外。

## 再現

リポジトリのルートから実行する。API認証も通信も不要。

```bash
.venv/bin/python research/financial-inputs-2026-10-05/reproduce.py
.venv/bin/python research/financial-inputs-2026-10-05/reproduce.py --check
```

`--check` は一時ディレクトリで再計算し、全成果物とprovenanceの一致を確認して削除する。
正式な入力契約・実売買条件は[過去検証](../../docs/operations/historical-replay.md)を参照する。

## Forward holdout

期間・入力源・実装ハッシュ・閾値の正本は
[事前固定した計画](../../operations/evidence/v04-holdout-plan.json)。
6回の正式月末評価、10件の正式取引、最大下落率-30%、単一銘柄寄与-10%、業種寄与-20%の
既存条件を保持した。10取引を得るために期間やルールを事後変更しない。
観測不足ならINCONCLUSIVE。取得完了や日次snapshotを評価回数・取引数へ加算しない。

[forward-holdout.yml](../../.github/workflows/forward-holdout.yml)はmainで毎日22:30 JSTに
保存済みデータと計画を読み取り、原本の世代と不足を派生artifactに残す。
APIキーを使わず、9役割の入力不足や凍結した実装の変更があれば合格しない。
開始日以降の入力不足はexit 1、実装変更はexit 2で報告する。
workflowのartifact保持指定は400日だが、10月6日に確認したrepositoryの実上限は90日。
長期保存は[一次資料のGit checkpoint](../../docs/operations/automation.md#一次資料とpaper調査準備)を使い、
正式な入力・結果の正本はGitで管理する。凍結した観測workflowは変更しない。

[開始前の確認](holdout-setup.json)では正式入力が未整備。
このworkflowは銘柄の開示レビューや未提供の指数を取得する処理ではない。
全母集団の採点・開示確認と、利用権のある日次指数を揃える必要がある。
期間終了後、9役割の正式入力が検証を通過したときだけ、同じ正式再生エンジンで
回数・損失条件を採点する。PAPER研究の事前固定は本人のLIVE承認を意味しない。
復旧試験は要求しない。

## 再実行

```bash
python research/formal-validation-2026-10-05/reproduce.py
python -m stock_jp research holdout observe --output .work/forward-holdout/observation.json
python -m stock_jp research replay --manifest research/historical-replay-2025-2026/input-manifest.json validate
```

最初のコマンドは通信せず、保存済み世代と原本から採点・MRS・出口の出力を一時生成し、
コミット済み結果と全ファイルのSHA-256を比較する。
最後のコマンドは正式入力が不足している現状ではexit 1が正しい。
過去の価格・資金配分診断は[前回の検証](../validation-2026-10-05/README.md)を参照する。

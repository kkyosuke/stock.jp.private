# 日本株運用状態・台帳仕様 v0.2

- 発効日: 2026年8月31日
- 状態スキーマ: `2.1`
- 保存先: public リポジトリでは追跡せず、親の private リポジトリで追跡する `operations/private/`
- 原則: 現在値だけでなく、そこへ至った不可逆イベントを追記型台帳に残す

## 1. なぜ状態v2が必要か

翌日の判定は、銘柄コードと現在株価だけでは再現できない。5倍・10倍の部分利確をすでに行ったか、`S-B`が何四半期続いたか、全売却後63営業日の再購入禁止中か、株式分割を反映済みか、回収資金が別候補へ実際に再配分されたかで行動が変わる。

`state.json`は実行全体の位置、CSV台帳は銘柄・資金・取引の詳細を正本とする。同じ事実をチャット履歴から推測しない。

## 2. 正本ファイル

| ファイル | 正本とする状態 | 更新規則 |
|---|---|---|
| `state.json` | 最終成功、カットオフ、未照合注文、連続成功回数、定期レビュー | 実行終了時に原子的に更新 |
| `portfolio-register.csv` | 保有、業種、Q0、倍率、利確フラグ、`S-B`連続数、再購入禁止 | 約定・決算・月末・コーポレートアクション後に更新 |
| `trade-event-ledger.csv` | 注文提案から仮想/実約定、取消、失効まで | 1イベント1行で追記。過去行を上書きしない |
| `recovered-capital-ledger.csv` | 5倍・10倍等の売却資金と再配分の有無 | 回収と割当を別イベントとして追跡 |
| `capital-ledger.csv` | 入出金、売買、費用、税、利用可能現金 | 1資金イベント1行で追記 |
| `corporate-actions.csv` | 分割、併合、コード変更等と正規化係数 | 適用前後と根拠URLを残す |
| `forecast-history.csv` | 会社IR、TDnet、EDINETから確認した会社予想の公表時点履歴 | `source_id`で重複排除し、後日の値で過去値を上書きしない |
| `share-count-history.csv` | 決算サマリー記載の期末発行済・自己株・平均株式数 | リアルタイム株式数とみなさず、希薄化確認の起点にする |
| `earnings-calendar-history.csv` | 決算発表予定の公表・変更・未定化履歴 | 旧予定を削除せず公表日順に残す |
| `rebuy-restrictions.csv` | 63営業日または恒久的な再購入禁止 | 全売却イベントから作成し、解除理由を残す |
| `industry-exposure.csv` | 適用ルール版の同一業種上限（v0.4は20%）の時点別集計 | 注文候補作成前と約定後に更新 |
| `market-regime-log.csv` | `MRS-v0.1`の時点別入力と結果 | 後日の改定値で過去行を上書きしない |
| `source-watermarks.json` | 情報源別の成功カットオフと最後の資料ID | 完了ゲート通過後だけ更新 |

正確な数量、金額、口座注文IDは`*_private`列だけに記録する。公開ログには比率と匿名化集計だけを出す。

## 3. 状態遷移

注文票を作っただけでは保有を変えない。次の順序で記録する。

1. `orders.csv`へ`PAPER_PROPOSED`または`PROPOSED`を作成
2. `state.json`の`unreconciled_ticket_ids`へticket IDを追加
3. 仮想約定、実約定、取消、失効の根拠が得られたら`trade-event-ledger.csv`へ追記
4. 約定イベントだけを`portfolio-register.csv`と`capital-ledger.csv`へ反映
5. 部分利確なら`five_x_taken`/`ten_x_taken`と`current_fraction`を更新
6. 全売却なら`rebuy-restrictions.csv`へ禁止期間を作成
7. 全台帳の数量・現金が一致した後だけticket IDを未照合一覧から除く

`PAPER`では証券会社の約定を捏造せず、固定した約定モデルによる`PAPER_FILL`として区別する。`LIVE`では利用者が入力した約定証跡なしに`FILLED`へしない。

## 4. 回収原資の扱い

5倍時の20%売却は税・費用控除前の投下額相当であり、税引後の元本回収を保証しない。回収額、推定原資相当額、再配分可能額を別々に記録する。

回収資金は合格候補があるだけでは再配分済みにしない。新しい候補が通常の入口条件、情勢指数、業種上限、流動性、ロット制約をすべて満たし、対応する約定が台帳へ記録された場合だけ`ALLOCATED`とする。候補がなければ`AVAILABLE`のまま戦略待機資金とし、固定的な安全資産には分類せず、機会損失を反実仮想で追跡する。

## 5. 移行と検証

既存のprivateログがある環境では、次を1回実行する。

~~~bash
.venv/bin/python scripts/operation_state.py migrate
.venv/bin/python scripts/operation_state.py validate
~~~

移行は旧ファイルを`operations/private/migrations/`へ一時 snapshot として退避してから列を追加し、既存値を保持する。同じ移行を再実行しても新しい snapshot や移行行を増やさない。privateディレクトリは`0700`、ファイルは`0600`へ補正する。

検証エラー、重複event ID、同一コードの重複保有、無効な利確フラグ、負の`S-B`連続数、未反映のコーポレートアクション、未照合ticketがある場合は、新規・追加注文を作らない。

# 日本株テンバガー実運用手順書 v0.1

- 状態: ペーパートレード運用用。実資金への昇格は[運用ガバナンス](operation-governance-v0.1.md)に従う
- 凍結日: 2026年8月31日
- 銘柄判定: `PAPER`では[v0.4](../rules/tenbagger-rule-v0.4.md)をベースライン、[v0.2](../rules/tenbagger-rule-v0.2.md)と[v0.3](../rules/tenbagger-rule-v0.3.md)をシャドー比較とする
- 対象: 日本株の新規購入、継続、追加、縮小、売却、情勢確認、注文、記録

本書は「良さそうだから今買う」という裁量を減らし、同じ情報なら同じ行動へ到達するための手順書である。v0.4では運用資産の100%をテンバガー戦略の対象にするが、投資比率を埋めるための強制購入はしない。初回5%、追加1回2.5%、1銘柄累計10%、同一業種20%、候補群100%は目標額ではなく絶対上限とする。未投資分は固定的な安全資産ではなく、合格候補または追加条件を待つ戦略待機資金として記録する。生活資金、納税資金、5年以内に使う予定資金、借入金を運用資産へ含めない。

運用モードとルール版は[運用ガバナンス v0.1](operation-governance-v0.1.md)を正本とする。平日1回の定時実行、日次レポート、注文候補、次回への引き継ぎは[日次自動実行手順書 v0.1](daily-automation-runbook-v0.1.md)に従う。日次タスクへ週次・月次・四半期の期限到来作業をまとめ、同じ銘柄を同じ理由で重複レビューしない。

## 1. 実資金を入れる前の停止条件

次のうち1つでも未完了なら、判定結果は `WAIT` とし注文を出さない。

1. 損失しても生活へ影響しない実運用予算を分離していない
2. 証券口座、税区分、売買単位、手数料、注文種別を確認していない
3. 対象銘柄を最新開示まで使ってv0.4が引き継ぐv0.2の全ハードゲートと100点スコアで再評価していない
4. 10倍逆算、SAM、SOM、直接競合、最大3つの主要KPIを購入前ログへ固定していない
5. 最新の情勢指数を計算していない
6. 指値、株数、上限金額、未約定時の行動を注文前に記録していない
7. 100株単位への切り下げ後も購入上限または流動性上限を超える
8. 判断に使った資料のURL、公開日時、取得日時を保存していない

公開リポジトリには資産総額、口座番号、認証情報、正確な保有数量を保存しない。実ログは親のprivateリポジトリが追跡する `operations/private/` に置く。公開用には、現在のポジションを推測できない比率と匿名化集計だけを残す。

## 2. いつ確認するか

| 頻度 | 時刻の目安 | 確認内容 | 通常の行動 |
|---|---|---|---|
| 毎営業日 | 取引終了後 | TDnet、EDINET、会社IR、売買停止、TOB、監査、決算訂正、資金調達、重大事故 | `S-A`候補だけ即時判定。株価だけでは売買しない |
| 注文日 | 8:45〜8:55 | 前日15:30以後の開示、売買停止、分割、気配、証券会社障害 | 新しい重要情報があれば注文を取り消して `WAIT` |
| 毎週末 | 土日 | 開示見落とし、直近20日平均売買代金、保有比率、決算予定、情勢指数の速報 | 原則売買せず翌週の作業を予約 |
| 各月末 | 15:30以後 | 全候補抽出、価格倍率、`MA20`、`DD20`、3年期限、集中、正式な情勢指数 | 翌営業日の購入・縮小・売却計画を作成 |
| 四半期開示後 | 5営業日以内 | 全ハードゲート、100点スコア、主要KPI、希薄化、資金余力、必要シェア | `KEEP`、`ADD`、`REDUCE`、`SELL` |
| 本決算後 | 10営業日以内 | SAM、SOM、競合、出口倍率、3年逆算 | 投資仮説を全面更新 |

毎日行うのは開示イベントの検知であり、毎日の値動きによる再採点ではない。通常の価格判断は月1回、企業進捗の判断は四半期ごととする。日中の含み損益を見て裁量売買しない。

## 3. 購入注文は朝一か午後一か

### 結論

朝一か午後一かを予想して選ばない。月末評価日の翌営業日 `T1` に、8:45〜8:55の開示確認後、9:00より前に当日限りの指値注文を置く。注文は1日有効とし、約定しなければ午後に指値を引き上げず、その月の購入は `WATCH` へ戻す。

東京証券取引所の現物株は前場9:00〜11:30、後場12:30〜15:30で、注文受付は8:00と12:05から始まる。15:25〜15:30はクロージング・オークションの注文受付時間である。取引時間は制度変更があり得るため、注文前にJPXと証券会社の最新仕様を確認する。

### 新規購入の執行手順

1. 月末 `T0` の15:30までに公表済みの情報だけで候補を確定する
2. `T1` の8:45〜8:55にTDnet、EDINET、会社IR、売買停止、分割を再確認する
3. 新しい重要情報があれば注文せず、ログを `WAIT-NEW-DISCLOSURE` にする
4. 注文上限価格はv0.4が引き継ぐv0.2どおり `1.15 × PE` とし、呼値単位へ切り下げる
5. 株数は「v0.4の初回・追加上限」「情勢指数反映後の上限」「候補群・業種・銘柄上限」「利用可能現金」「流動性上限」の最小値を100株単位へ切り下げる
6. 寄り前に当日限りの指値を置き、成行、引成、成行化する不成注文は新規購入に使わない
7. 一部約定は約定分だけを初回購入とし、残りを追わない
8. 未約定なら失敗ではなく `WATCH-NOT-FILLED` とし、次の月末まで全項目を再評価しない

この方式は朝の方が上がる、午後の方が安いという未検証の仮説を使わない。指値により最大価格を先に固定し、時間帯選択を利益源にしない。

### 売却の執行

- 通常の月末・決算売却は翌営業日から指値を使い、1日の売却額を直近20日平均売買代金の5%以下にする
- `S-A`の即時全売却は価格予想より撤退を優先し、次に売買可能な営業日から参加率10%以下で分割する
- 売買停止、特別気配、値幅制限、買い手不在では想定価格で売れたと記録しない
- 同じ日に複数条件が成立したら、即時全売却、決算全売却、価格・時間全売却、部分売却の順とする

## 4. 情勢指数 `MRS-v0.1`

### 4.1 目的

情勢指数は銘柄の100点スコアへ加点・減点しない。新規購入と追加購入の金額だけを抑える独立したリスク予算レイヤーとする。指数だけを理由に既存銘柄を売却せず、企業固有の撤退条件を解除しない。

### 4.2 月末の5項目

各項目を満たせば1点、満たさなければ0点とし、後から重みを変えない。

| ID | 1点となる条件 | 意味 |
|---|---|---|
| `M1` | TOPIX月末終値が200営業日移動平均以上 | 日本株全体の長期トレンド |
| `M2` | 東証グロース市場250指数月末終値が200営業日移動平均以上 | 小型成長株の長期トレンド |
| `M3` | 対象母集団の50%以上が200営業日移動平均以上 | 時価総額加重指数だけでは見えない市場の広がり |
| `M4` | 日経平均VIが直近3年の日次値80パーセンタイル以下 | 極端な予想変動の回避 |
| `M5` | 内閣府景気動向指数の先行CI最新値が3か月前以上 | 実体経済の方向 |

| 合計 | 状態 | 新規・追加の上限倍率 |
|---:|---|---:|
| 4〜5 | `NORMAL` | 1.0 |
| 2〜3 | `CAUTION` | 0.5 |
| 0〜1 | `STRESS` | 0.0。次の月末まで新規・追加を見送る |

すべての移動平均、パーセンタイル、景気動向指数は、その月末までに取得または公表されていた値だけで計算する。後日の改定値で過去ログを上書きせず、改定は新しい取得日時の別行として残す。

v0.4の初回購入上限は `5% × 上限倍率`、1回の追加上限は `2.5% × 上限倍率` とする。たとえば `CAUTION` なら初回2.5%、追加1.25%が上限となる。100株で上限を超えるなら購入しない。1項目でも必要データが取得不能なら状態を `UNAVAILABLE` とし、新規・追加を行わない。v0.2とv0.3のシャドー判断では、それぞれの凍結済み1%・0.5%上限を使う。

これは期待収益を予測する完成済みモデルではなく、未検証の保守的なパイロット制御である。通常の1%を買った場合の反実仮想もログへ残し、見送った候補のその後を追跡する。閾値変更は未見期間の評価後に別版として行う。

`scripts/market_regime.py` で同じ計算を再現する。

~~~bash
.venv/bin/python scripts/market_regime.py \
  --as-of 2026-08-31 \
  --topix-close 100 --topix-ma200 95 \
  --growth-close 100 --growth-ma200 105 \
  --breadth-pct 48 \
  --nikkei-vi 25 --nikkei-vi-p80-3y 30 \
  --leading-ci 101 --leading-ci-3m-ago 100
~~~

日銀短観、政策金利、為替、地政学イベントは会社ごとの売上・原価・資金調達へ与える影響を四半期レビューで記録するが、主観的な重複加点を避けるため `MRS-v0.1` へ混ぜない。取引所障害、証券会社障害、価格データ異常時は指数に関係なく新規注文を停止する。

## 5. 銘柄の進捗をどう判定するか

行動語彙は `BUY / WATCH / WAIT / KEEP / ADD / REDUCE / SELL / NO-ACTION` に固定する。

| 行動 | 判定 |
|---|---|
| `BUY` | 全ハードゲート通過、`S >= 70`、市場余地8点以上、逆算可能性10点以上、10倍逆算成立、流動性合格、`MRS`が`NORMAL`または`CAUTION` |
| `WATCH` | 銘柄条件は満たすが未約定、次の月末待ち、または資料更新待ち |
| `WAIT` | 重要データ不足、情勢指数`STRESS`/`UNAVAILABLE`、新開示の再評価中、売買単位・流動性不適合 |
| `KEEP` | 即時・決算・価格売却条件がなく、四半期スコア70点以上で10倍逆算が維持 |
| `ADD` | 四半期開示後だけ。`S >= 75`、必要売上CAGR悪化なし、希薄化見通し増加なし、5倍未到達、全上限内 |
| `REDUCE` | 適用中ルール版の部分利確・決算縮小条件、または集中縮小が成立。シャドー版の成立は実行せず反実仮想へ記録 |
| `SELL` | `S-A`、2四半期連続の該当`S-B`、3年期限、10倍後50%トレーリングなどの全売却条件が成立 |

「進捗が良い」は株価上昇ではなく、購入前に固定した主要KPI、1株当たり粗利益、必要売上CAGR、必要シェア、希薄化、資金余力が基本シナリオ以上であることを指す。ニュースの印象だけで `ADD` しない。株価下落だけを理由に平均取得単価を下げない。

## 6. 1週間の運用手順

### 毎営業日終了後

1. 保有銘柄と注文中銘柄をTDnetで検索する
2. EDINETと会社IRで法定開示・補足資料を確認する
3. `S-A`候補だけを即時レビューし、その他は週末キューへ入れる
4. 日中株価を理由とする行動は記録しない

### 週末

1. 開示見落としと翌週の決算予定を確認する
2. 直近20日平均売買代金と保有比率を更新する
3. 情勢指数を速報更新するが、正式な購入額変更は月末値で行う
4. 各銘柄の次回レビュー日と不足資料を記録する
5. 判断しなかったことも `NO-ACTION` と理由を残す

### 月末

1. 対象母集団をpoint-in-timeで再抽出する
2. 新規候補を全項目で採点する
3. 保有銘柄へ`operation-policy.json`の適用中ルール版の価格・時間条件を適用し、シャドー版は反実仮想として別記する
4. `MRS-v0.1` を確定する
5. 翌営業日の全注文について判断ログを作る
6. 人間が数量、指値、根拠URLを再確認してから証券会社へ手入力する

### 四半期開示後

1. 最大3つの主要KPIを実績と基本シナリオで比較する
2. 100点スコア、希薄化、資金余力、SAM/SOM、10倍逆算を更新する
3. `KEEP`、`ADD`、`REDUCE`、`SELL`のいずれか1つをルールID付きで決める
4. 例外扱いは金額、終了日、次回確認条件を記録する

## 7. ログの作り方

判断ログは[テンプレート](../../operations/templates/decision-log-template.md)から作成するか、次のコマンドでprivate領域へ生成する。

~~~bash
.venv/bin/python scripts/new_operation_log.py \
  --date 2026-08-31 \
  --code 0000 \
  --company SAMPLE \
  --mode monthly
~~~

最低限、次を記録する。

- 判断日時と情報カットオフ
- `BUY/WATCH/WAIT/KEEP/ADD/REDUCE/SELL/NO-ACTION`
- 成立したルールIDと不成立を確認した重要条件
- 事実、計算、判断を分けた根拠
- TDnet、EDINET、会社IR等のURLと公開日時
- スコア、主要KPI、10倍逆算、流動性、情勢指数
- 注文種別、指値、予定比率、有効期限、実際の約定
- 次回レビュー日
- 手数料、税、スリッページ、見送った場合の反実仮想

保有一覧は[portfolio-register.csv](../../operations/templates/portfolio-register.csv)、情勢指数の履歴は[market-regime-log.csv](../../operations/templates/market-regime-log.csv)の列を使う。日次実行は[daily-report-template.md](../../operations/templates/daily-report-template.md)、[order-ticket-template.csv](../../operations/templates/order-ticket-template.csv)、[pretrade-check-template.md](../../operations/templates/pretrade-check-template.md)を使う。実数値を含むファイルは `operations/private/` へコピーし、テンプレート自体を直接編集しない。

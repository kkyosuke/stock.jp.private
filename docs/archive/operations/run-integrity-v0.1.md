# 夜間運用の完了条件・重複防止 v0.1

- 発効日: 2026年8月31日
- 対象: `scripts/daily_operation.py`で作成する1日1回の運用
- 安全側の既定値: 確認できない実行は`failed`とし、開示カットオフを進めない

## 1. 実行所有権

`prepare`は6時間有効の`run_token`を返し、privateの`lease.json`へ保存する。同じ日付を別プロセスがtokenなしで開始すると`locked`となる。同じ実行を継続するときだけ`--run-token`へ返された値を渡す。期限切れまたは`failed`後は新しいtokenで再開し、試行番号を増やす。

`complete`と`fail`は所有中のtokenがなければ拒否する。tokenは認証情報ではないが、privateログの実行制御値なので公開ファイルへ転記しない。

## 2. 完了マニフェスト

`coverage.json`は開始時に次を固定する。

- 保有銘柄
- 前日までの未照合注文
- activeな監視銘柄
- 期限到来レビュー
- 必須の公式情報源
- 前回成功時の開示カットオフ

夜間調査後、各`expected`を確認したものだけ`checked`へ移し、公式情報源を`CHECKED`にする。optionalな会社IRだけは対象銘柄がなければ`NOT_APPLICABLE`にできる。確認した公式情報源ごとに、検索結果が0件でも検索範囲を示す証跡行を`sources.csv`へ残す。

## 3. `complete`が拒否する条件

- 日次レポートが`COMPLETED`でない、またはカットオフ・株価日・総合結果が未確定
- `coverage.json`の対象に未確認がある
- 公式情報源スキャンが未実行、または`research-queue.json`に未処理タスクがある
- TDnet、EDINET、JPX、対象会社IRの必須確認が完了していない
- `sources.csv`に公式情報源ごとの証跡がない、ID重複、URL・日時不正、カットオフ後の資料が混入
- 重大なデータ不足、または影響と再試行日時を持たないデータ不足がある
- 注文票の運用モード、ルール版、状態がポリシーと違う
- ticket IDまたは同一コード・売買区分・取引日の注文が重複
- 前日までの同一コード注文が未照合
- 完了時刻より後のカットオフ、後退するカットオフ、所有権のない実行

検証に失敗した場合、レポートと部分調査はそのまま残り、tokenの有効時間内に修正して再度`complete`できる。取得そのものが不可能なら`fail`で閉じる。

## 4. 情報源ウォーターマーク

成功後だけ`source-watermarks.json`へTDnet、EDINET、会社IR、JPXごとの成功カットオフと最後の`(published_at, source_id)`を保存する。次回取得はウォーターマークの10分前から重ねて検索し、source IDで重複排除する。これにより同一時刻の複数開示と遅延到着を吸収する。

全体の`state.json.last_disclosure_cutoff_jst`も、完了マニフェストの検証後だけ進む。`failed`、空レポート、情報源0件では進まない。

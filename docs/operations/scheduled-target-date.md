# schedule対象日の固定と再試行

scheduleは初回起動時点で直近の21:00 JSTを迎えた日を対象にする。
例えば翌日00:01に遅延起動した場合は前日分となる。GitHubの予定起動日を推測せず、
対象日と解決時刻をrun IDごとにcheckpointへ先に保存する。同じrunの再試行は翌日でも
保存した対象日を使う。保存確認に失敗した場合は取得を開始しない。
後日の未完了journalは、公開前の `WAIT_PUBLICATION` で要求・結果・エラーがなく、
checkpointと復元ファイルが一致する場合だけ、そのまま残して今回の対象日の処理を進める。
送信済み・結果不明の要求や設定hash不一致を、この扱いで解除することはない。

手動実行は対象日の明示指定を維持し、未指定なら実行時点のJST日付を使う。
既存のcheckpointは読込み可能。`scheduled_targets` を保存した後は、この項目に
対応しない旧版のrunnerはcheckpoint検証で停止するため、再試行にも対応版を使う。
